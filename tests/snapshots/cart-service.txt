-- Findings --
warn: RECEIPTS_TABLE and TOPIC_ARN aren't set on CheckoutFunction, and its code reads them with os.environ[...] (cart/app.py line 16 and cart/app.py line 31): that line fails with KeyError: 'RECEIPTS_TABLE', when Lambda loads the code, so every call fails. Add them to its environment variables (the console's Configuration tab, Environment variables).
warn: PostgreSQL DELETE at cart/db.py line 27 in clear_cart() puts event body (JSON).customer into the SQL text itself, so whoever sends it can change the statement (SQL injection). Pass it as a parameter instead: execute("... WHERE id = %s", (value,)).
info: PostgreSQL SELECT runs once per item in for item in cart['items'] (cart/db.py line 20), a round trip for each, where one query for all of them (WHERE ... IN (...), or a join) would need fewer.
warn: The OpenAI client made at cart/assistant.py line 7 has no timeout, so a call through it waits up to 10 minutes a try (the SDK's default timeout), and it tries 3 times: if OpenAI doesn't answer, the run waits until Lambda stops it at its 15 s timeout, and you pay for the wait. Give it one where it's made: OpenAI(timeout=20, max_retries=1).
info: It opens a new PostgreSQL connection on every call, at cart/db.py line 14 in connect(): that's a round trip or more before any work, and many runs at once can use up the server's connections. Make it once at module level (above the handler), so warm calls reuse it.
warn: CheckoutFunction's role in template.yaml (it has DynamoDBReadPolicy) doesn't allow dynamodb:PutItem and sns:Publish, which DynamoDB PutItem at cart/app.py line 29 and SNS Publish at cart/app.py line 31 need: those calls fail with AccessDenied. Add DynamoDBWritePolicy and SNSPublishMessagePolicy to CheckoutFunction's Policies in template.yaml.
